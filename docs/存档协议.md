# JSON 存档协议

单机存档是 UTF-8 JSON，文件头为 `kind: "partyquiz-save"`。新存档使用 `saveSchemaVersion: 2`、`rulesVersion: 5`、`writerAppVersion: "6.1.0"`，阅读器版本为 7。规则 5 对局或含有规则 5 历史记录的存档，最低阅读版本为 7。只含旧规则的存档保留其内容所需的最低阅读版本。

## 题包身份

`questionPack` 保存题包的 `id`、`version`、`schemaVersion` 和内容 `fingerprint`。游戏状态只保存题包引用。正式内置题库和导入的自定义题库在运行时分别存储，当前对局使用的题库内容会冻结。导出的游戏存档只包含引用，使用自定义题库的游戏仍须另外导出该题库。

## 游戏状态

`state.game` 保存规则版本、题量、题板分配、已出现题目、当前题目、玩家、判分历史和结束状态。题板等级为内部 1–8：选择题使用 1–4，简答题使用 5–8。选择题分值为 100、200、300、400，简答题分值为 200、400、600、800。

规则 5 保留规则 4 的已作答计分。新增 `history.pass` 和 `passReason`：普通弃答为全员空判断、零分，已锁定抢答者放弃为 `passReason: "abandon"`，只有该玩家判断为错并扣半分。`Core.scoreRecord` 是计分和存档验证的共同入口。旧规则 2/3/4 不接受新增弃答标记，也不使用新规则重算成绩。

轮流题量是人数的整数倍。有效轮次等于已确认且未作废的历史数量，弃答消耗机会，作废不消耗。作废旧题保存在 `retired`，同档替换题占用原题板位置。已展示的旧题不会重新抽取，恢复时同时验证题板、已见题、作废记录和历史之间的关系。

## 结果历史

结束对局后，程序自动生成紧凑的结果历史快照并保存到本地运行状态。导出存档时，`state.resultsHistory` 会随存档导出，导入时按对局 ID 合并。快照只保存题目摘要和判分所需信息，不重复保存整套题库。

## 版本兼容

- 阅读器 7 继续读取旧 `saveSchemaVersion` 1/2 及规则 2/3/4。规则 5 必须使用存档 schema 2。
- 旧规则记录保留原有计分方式。规则 5 新增字段不会被解释为旧对局的有效作答。
- 题包 ID、版本或内容指纹不匹配时，存档必须拒绝导入。恢复未结束对局需要匹配的题库。
- 发行包本身不附带历史记录、活动对局或玩家姓名。浏览器中已有的对局和历史记录会继续保留，之后的状态也会自动保存；外部 JSON 只有在用户主动导入时才会读取。
- 题库导入失败时保留当前题库。导入成功的自定义题库存入浏览器运行时存储，空间不足或权限失败会显示错误并要求重试。

内容指纹用于检测内容变更，不是加密签名。存档和题库导出、导入都需要用户主动操作。

## 联机历史

联机记录单独保存在 IndexedDB，按对局 ID 合并。新记录为 `protocol: 2`、`rulesVersion: 2`。每道题保留所有座位的记录，`status` 为 `answered`、`passed`、`timeout` 或 `notTurn`。后三类均为零分，轮流模式的非当轮玩家不计入作答机会。

选择题和简答题先生成待确认结果，只有 `confirmScore` 写入历史和总分。当前题的单份复核先撤回本题已确认分数，保留锁定答案和其他判定，再确认时只替换一次。旧联机规则 1 的历史仍按原来的缺答扣分规则读取。

# JSON 存档协议 · V5.10

存档是 UTF-8 JSON，文件头为 `kind: "partyquiz-save"`。V5.10 新存档使用 `saveSchemaVersion: 2`、`rulesVersion: 4`、`writerAppVersion: "5.10.0"`，阅读器版本为 6。新规则对局或含有新规则历史记录的存档，最低阅读版本为 6。只含旧规则的存档会保留其内容所需的最低阅读版本。

## 题包身份

`questionPack` 保存题包的 `id`、`version`、`schemaVersion` 和内容 `fingerprint`。游戏状态只保存题包引用。正式内置题库和导入的自定义题库在运行时分别存储，当前对局使用的题库内容会冻结。导出的游戏存档只包含引用，使用自定义题库的游戏仍须另外导出该题库。

## 游戏状态

`state.game` 保存规则版本、题量、题板分配、已出现题目、当前题目、玩家、判分历史和结束状态。题板等级为内部 1–8：选择题使用 1–4，简答题使用 5–8。选择题分值为 100、200、300、400，简答题分值为 200、400、600、800。

规则版本 4 的一起抢答中，选择题和简答题答对加完整分值，答错扣一半。一起回答中，选择题答错不扣分，简答题答错扣一半。轮流回答中，选择题答错不扣分，简答题答错扣一半。旧规则版本 2/3 的记录按原规则验证，不会被新规则重新计分。

## 结果历史

结束对局后，程序自动生成紧凑的结果历史快照并保存到本地运行状态。导出存档时，`state.resultsHistory` 会随存档导出，导入时按对局 ID 合并。快照只保存题目摘要和判分所需信息，不重复保存整套题库。

## 版本兼容

- V5.10 写入 Reader 6 可读取的存档，并继续读取旧 `saveSchemaVersion` 1/2 及 `rulesVersion` 2/3。
- 旧规则记录保留原有计分方式。新规则记录使用 `rulesVersion: 4`，避免旧的一起抢答记录被重新解释。
- 题包 ID、版本或内容指纹不匹配时，存档必须拒绝导入。恢复未结束对局需要匹配的题库。
- 发行包本身不附带历史记录、活动对局或玩家姓名。浏览器中已有的对局和历史记录会继续保留，之后的状态也会自动保存；外部 JSON 只有在用户主动导入时才会读取。
- 题库导入失败时保留当前题库。导入成功的自定义题库存入浏览器运行时存储，空间不足或权限失败会显示错误并要求重试。

内容指纹用于检测内容变更，不是加密签名。存档和题库导出、导入都需要用户主动操作。

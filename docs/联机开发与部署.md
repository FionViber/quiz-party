# 联机开发与部署

单机规则与界面位于 src/。联机界面位于 online/，房间服务位于 worker/。两者共用 data/packs/builtin-bank.json，由构建工具生成各自需要的产物。

## 本地运行

准备 Node.js 24、Python 3.10 或更新版本，以及 pnpm。执行 pnpm install 安装构建工具。Python 程序不在 PATH 中时，将 PYTHON 环境变量设为其完整路径。

工具 tools/dev-setup.mjs 从标准输入读取管理员密码，生成加密页面、本地开发凭据和 D1 题库。密码不作为命令行参数传入。之后运行：

    node node_modules/wrangler/bin/wrangler.js dev --config worker/wrangler.jsonc --port 8787 --ip 127.0.0.1 --local
    python -m http.server 8610 --bind 127.0.0.1 --directory dist-online

打开 http://127.0.0.1:8610/。修改公开界面后重新运行 node tools/build-online.mjs http://127.0.0.1:8787，再刷新浏览器。修改管理员模块后，重新运行 dev-setup.mjs --skip-db，仍通过标准输入提供密码。

## 构建

- tools/build-admin.mjs 将完整单机 HTML、管理员界面和管理员签名凭据放入 AES-GCM 加密载荷。
- tools/build-online.mjs 后跟 API 地址，生成公开入口、玩家界面、静态资源和内容指纹。
- admin.enc.js 是发布用的加密载荷。admin.enc.json 只用于私有构建和测试，不放进发行包。
- 已有加密载荷存在时，同一个密码会复用管理员签名凭据。单纯修改代码不会轮换后台管理员身份。
- 从源码发行包重新构建已有部署时，先把成品包的 admin.enc.js 放到 dist-online/，再构建管理员内容，保留现有签名身份。
- 主动更换密码时，用 build-admin.mjs --rotate-credential 生成新凭据，并同步更新后台公钥。服务端签名密钥由 Cloudflare Secret 保存。

源码中不保存管理员密码、解密密钥或服务端签名密钥。worker/admin-public-jwk.json 只含公开验证密钥。

## Cloudflare

后台使用 Workers、SQLite Durable Objects 和 D1，均采用免费计划支持的能力。费用与额度以该 Cloudflare 账户的当前计划为准。

首次部署时创建 D1 数据库，将返回的 ID 传给：

    node tools/prepare-cloud.mjs <D1数据库ID>
    node node_modules/wrangler/bin/wrangler.js d1 migrations apply quiz-party --remote --config worker/wrangler.production.jsonc
    node tools/seed-bank.mjs
    node node_modules/wrangler/bin/wrangler.js d1 execute quiz-party --remote --config worker/wrangler.production.jsonc --file private/bank.sql
    node node_modules/wrangler/bin/wrangler.js deploy --config worker/wrangler.production.jsonc
    node tools/init-service-secret.mjs

init-service-secret.mjs 只在缺少 TOKEN_SECRET 时生成随机密钥，并经标准输入上传。密钥不写入仓库或本地文件。常规更新保留现有密钥。

题库不变时不必重复导入。更新后台后，使用部署输出中的 Worker 地址重新构建公开网页。

## GitHub Pages

用部署后的 HTTPS API 地址运行 build-online.mjs，再运行：

    python tools/package-online.py

工具按文件清单生成 private/release/Quiz-Party/、Quiz-Party-Source/ 及两份 ZIP。发布 Quiz-Party/ 的内容到 gh-pages。工具排除 admin.enc.json、原始 src/、原始题库、source map、测试文件、开发数据库、缓存和私有配置。单机代码与题库在发布页面中只通过管理员加密载荷提供。

只需网站文件时使用 --stage-only。预览构建可以给 build-online.mjs 传入第三个参数作为浏览器存储命名空间，再用 package-online.py --preview --stage-only 打包。正式发布必须使用空命名空间，保留现有用户存档。

仓库的公开源码和旧提交不会因为加密新页面而消失。页面加密负责保护新发布载荷，创建房间和主持操作还需要后台权限校验。

## 同步与记录

现行联机协议为 2。后台以 quiz-party-api-v2 单独部署，旧协议服务可以继续服务已有页面。新网页与新后台使用相同协议，遇到旧房间会明确提示重新开局，旧历史仍可导入。

房间阶段依次为大厅、选题、准备、作答、判分或复核、积分待确认、本题结果。准备阶段不发送题干和选项。只有主持人发题才开始服务器倒计时，只有确认积分才写入历史。轮流索引从已确认历史派生，复核或作废无需另行维护一个可漂移的轮次计数。

已开始的对局空闲两小时后自动结束，只保存已确认的成绩，并保留结果供原有身份恢复。未开局大厅过期时直接关闭。已结束的房间保存一天，在线身份从签发时起有效一天。自动结束与普通结束均会向在线参与者推送最终快照，触发本机历史保存。

每个房间由一个 Durable Object 顺序处理操作。请求带有操作 ID，答题操作还带当前题目 ID，选题操作带当前选题轮 ID。重复请求不会重复计分，上一轮的请求不能修改下一轮。

服务器决定截止时间。客户端通过 WebSocket 收到视图，使用单调时钟显示倒计时。未变化的历史记录不会在每次投票时重复广播，客户端在同一连接内保留最近的完整历史。重连总会收到完整初始状态。

结束后的联机记录按对局 ID 存入浏览器 IndexedDB。导入先验证整份记录，再通过一个事务写入。多标签页同时保存不同对局时不会互相覆盖。

## 授权

管理员在浏览器解密签名凭据，再对服务端的一次性 challenge 签名。后台验证后签发短期管理员会话。创建房间必须有管理员会话，主持人重新连接还必须同时持有房间身份和管理员会话。

加入房间不需要管理员密码。房间码只用于找到房间，加入后取得的随机身份负责区分玩家。答题和投票接口不接受客户端直接指定分数或主持人身份。

## 验证

开发测试与测试数据保留在本地工作区，不随成品或源码发行包发布。发布前验证纯规则、持久化、加密、权限、截止时间、32 客户端并发、断线重连，以及桌面和手机布局。用真实下载的 PNG 核对完整排名、两类图表和时长。
